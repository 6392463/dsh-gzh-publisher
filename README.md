# dsh-gzh-publisher

把一篇文章按公众号那套排版渲染成微信 HTML（正文配图**自动压到 1MB 以内**再传微信图床），然后通过**你自己配的代理**把成品推进**公众号草稿箱**。带一个三栏面板：左边选稿选号、中间看排版、右边推送和台账；账号、密钥、代理、配色全部在面板右上角的「设置」里配，**不需要改代码，也不需要任何个人的生产机**。

- **只到草稿箱**：面向个人订阅号（无发布权限）——全流程只调 `token` / `uploadimg` / `add_material` / `draft/add` / `draft/batchget`，不含任何发布类接口，成稿要人工在公众号后台点发布。碰到 `48001` / `200002` / `200003` 这类权限错误，提示里直接写「个人订阅号没有该接口权限，本插件只支持草稿链路」。
- **推送有闸门**：必须先有一次成功的渲染（`gzh_render` 产出 + `renderId` 进台账），面板的推送按钮才会亮，宿主还会再校验一遍文件内容确实等于那次渲染的产物。「点了个按钮结果推了一份没排版过的 HTML」这条路被从两头堵掉了。
- **推前先体检**：正文里**非图床配图**（推上去显示不出来）、**站外链接**（未认证个人订阅号点不开）、以及**草稿箱里已有的同名草稿**（产线推过的这里看不见）都会在联网前逐个点名拦下，确认要带风险就 `force: true` + `reason`，结论写进台账。
- **评论区开关**：账号级默认 + 单次推送覆盖（`commentOpen` / `commentFansOnly`），推之前就定好，不用每次推完再去后台补。
- **密钥只写不回显**：AppSecret / 代理 Token 只走写入路径，工具与面板一律显示 `****尾4位` 或「已配」。
- **防重复推送**：`账号 + 标题 + 正文` 指纹进台账，命中就拒推，除非显式 `force: true` 并写明 `reason`。草稿重复是生产事故，这里故意做成要人拍板。
- **面板和 agent 用的是同一份实现**：面板按钮最终调的就是 `gzh_*` 工具本体，fail-close、掩码、闸门、台账只有一套规则，不存在「页面上能过、工具里不能过」。

## 首次配置（五分钟）

1. 装好插件，左侧边栏点 **公众号草稿**（第一次可能要重启一次 DSH，见「已知限制」）。
2. 面板右上角点 **设置** → **新建账号**，填：
   - `key`：自己起，之后引用它（小写字母数字 `-_`）
   - 显示名、`appid`、`appsecret`（`appid` 在公众号后台「设置与开发 → 基本配置」）
   - `proxyUrl` + `proxyToken`：微信 API 代理地址与鉴权头；留空 `proxyUrl` 需要在插件配置里打开 `allowDirectApi`，并把本机出口 IP 加进公众号后台的 IP 白名单
   - 排版皮肤：从下拉里选一套（内置 4 套，或自己在「排版皮肤」页新建一套）
   - 评论区：默认「开放评论」；勾上「仅关注者可评论」则只有粉丝能评（写进草稿，推完在后台还能改）
3. 保存后回到面板，左上角**点一下账号**就选中它。
4. 左边选一篇「自媒体工作台」的产出；没有工作台也没关系——那一栏会自动变成 Markdown 粘贴框，把正文粘进去。
5. 右边点 **渲染并传图** → 中间就是排好的版式，**先看** → 满意了点 **推送到草稿箱** → **回读草稿箱** 确认真的进去了。

配一次号之后，日常就是「选号 → 选文 → 渲染 → 看 → 推」。想换配色：设置 → 排版皮肤 → 新建，把 7 个颜色字段填上，再回到「账号」里选给它。

## 面板在哪、长什么样

- 左侧边栏 → **公众号草稿**；DSH 设置 → 插件 → **公众号草稿推送**（`dsh-gzh-publisher`）是全局参数（默认皮肤、图片预算、超时等）。
- **左栏**：点选账号、点选文章（工作台不可用时是 Markdown 粘贴框）、「用当前账号的皮肤出一份样稿」。
- **中栏**：大号预览，就是要推的那份东西的版式——字号、行距、卡片、配图都在。审阅在这里做。
- **右栏**：一行状态 + 一行「下一步点哪」，然后 `只渲染（不传图）` / `渲染并传图` 并排，`推送到草稿箱` 是这一栏唯一的大主按钮（渲染成功前是灰的，推完自动再锁上），`封面与插图交给插件排` 是个开关，右边挂 `回读草稿箱`；再往下才是本次渲染明细、渲染记录、推送台账。
- **设置弹窗**：账号增删改（密钥只写不回显；含「开放评论 / 仅关注者可评论」两个开关）／排版皮肤增删改／全局参数（只读，指回插件配置页，避免一份配置两个入口）。关掉了评论的账号在左栏带 `评论关` 标记；代理、皮肤缺失、缺密钥这些细节收进鼠标停住时的 `title`，别推到才发现。
- **顶部横幅成功就一句话**：`已渲染《标题》· 3 节 / 12 段 / 配图 4 张 · 18KB`，有警告再加 `⚠ 2 条（见右栏）`；推送成功是 `已进草稿箱 · 《标题》· media_id=…`。结构、封面、摘要、插图位置、renderId 右栏「本次渲染」逐行都有，封面与正文图数台账行也有，横幅不重复抄一遍；只有 `封面 ✗` / `摘要 ✗` 这两个「不点推送就发现不了」的硬缺留在横幅上当标记。失败才长——工具的 message + hint 原样贴出来，那是给人照着修的。smoke 里有断言盯着这条契约，别把它改回长段落。
- **界面上的字都当标签，不当说明书**（同一套契约，别回退）：字段名只写名字，前提和后果挂 `title` 悬浮；常驻提醒（插件停用 / 没配号 / 上次操作结果）都带 `×`，看过就能收掉；面板自己用一行说下一步点哪（`nextStep()`），左中右三栏不再各写一段引导；`本次渲染` 里的 `✗` 只写后果，补救办法压成一句；皮肤 key 格式、直连前提这类细节全在 `title` 里。**删掉的解释必须在别处找得到**——`title`、右栏明细、渲染记录 / 推送台账，去重不等于删信息。列表行和页签都能 Tab + Enter 走。`node tests/copy-scan.mjs` 扫超过 34 字的文案，剩下的应该基本都是 `title`。

## 工具（agent 走的这条，共 12 个）

| 工具 | 干什么 |
| --- | --- |
| `gzh_account_list` | 看已配置的账号（掩码）、默认号、皮肤、最近 5 条推送台账 |
| `gzh_account_set` | 新增/修改一个账号（合并式；密钥字段写一次，传空串删除；`comment: { open, fansOnly }` 配默认评论区） |
| `gzh_account_remove` | 删账号（推送台账保留，它是历史事实） |
| `gzh_skin_list` | 列内置 + 自定义皮肤（含每套的 7 个颜色值） |
| `gzh_skin_set` | 新建/修改自定义皮肤（内置皮肤不可覆盖） |
| `gzh_skin_remove` | 删自定义皮肤 |
| `gzh_config_get` | 读当前生效的全局参数、每项的中文说明、可编辑位置、压图引擎状态 |
| `gzh_media_desk` | `list` 看工作台有哪些成稿，`read` 取某条的正文和配图 |
| `gzh_layout_preview` | 用内置样稿生成某套皮肤的预览 HTML（不联网、不上传），用来核对配色 |
| `gzh_render` | 渲染：取稿 → 定封面、把配图排到各节 → 压图 → 排版 → 传图 → 落盘 `out/*.html`，返回 `renderId`、结构统计、`cover`（封面是谁定的、为什么）与 `placement`（每张插图落在哪一节、为什么）。`cover` 可指定封面，`autoPlace: false` 关掉自动挑封面/插图 |
| `gzh_push_draft` | 把渲染产物推成草稿（要求 `htmlPath` + `renderId`），返回草稿 `media_id` 与 `cover` / `stats.bodyImages`；没封面或正文没图会被拦住；可选 `commentOpen` / `commentFansOnly` 覆盖评论开关、`checkDraftBox: false` 跳过同名预检 |
| `gzh_draft_verify` | 回读草稿箱，确认那条草稿真的在、标题一致 |

标准链路：`gzh_media_desk`（或直接给 `markdown`）→ `gzh_render` → `gzh_push_draft` → `gzh_draft_verify`。

## 排版皮肤

内置 4 套，同一套骨架只差配色和小标签（`INSIGHT / WHY / HOW / ACTION / WARNING`）：

| key | 显示名 | 主色 |
| --- | --- | --- |
| `teal` | 青绿 | 墨绿，默认 |
| `sage` | 灰绿留白 | 低饱和灰绿 |
| `redwhite` | 红白 | 红底白字卡片 |
| `graphite` | 石墨 | 石墨灰 |

皮肤就是 7 个颜色字段，可在设置里或 `gzh_skin_set` 里自建一套：`accent`（主色）、`cardBg`、`cardBorder`、`underline`、`quoteBg`、`quoteText`、`heading`。只收 `#RGB` / `#RRGGBB`（颜色值会直接插进 `style`，所以别的写法一律拒绝并点名）。key 规则 `^[a-z0-9][a-z0-9_-]{1,31}$`。

账号还能带自己的 `skin: { "accent": "#1F6FEB" }` 做局部覆盖，不必新加一套代码；`eyebrows` / `foot` / `tail` 分别管每节小标签、落款、文末「资料领取」尾巴。

> 旧版本的皮肤 key 是按使用者自己的号名起的。现在内置的是上表的中性 key，**已配置的账号会在插件启用时自动迁移**（`layout` 与 `defaultLayout` 都改）；`src/layout.js` 的 `LEGACY_SKIN_KEYS` 保留「老名字 → 中性 key」这张映射表（公开仓库里只放中性别名示例，你自己的老名字加进去即可）。**表里查不到的老名字不会炸**：按未知皮肤处理，退回账号或全局默认皮肤，去设置里重选一次就行。

## 渲染 → 推送的闸门

`gzh_push_draft` 在联网之前依次检查（面板按钮只是把这套规则显示出来，拦不住它自己也会拦）：

1. 标题按「字」算不超过 64（emoji 记 1 字，不会劈开代理对）；摘要超过 120 字自动截断，而不是整篇被微信打回。
2. `htmlPath` 存在，且内容以内层 `<section>` 开头 —— 也就是排版产物，不是一篇裸 HTML（真有需要就显式传 `allowRawHtml: true` + `reason`，会进台账）。
3. `renderId` 找得到（渲染记录里，`gzh_render` 的返回值），且文件的 sha256 与那次渲染记录一致 —— 渲染完偷偷改文件会被发现。
4. 渲染记录的账号 = 要推的账号 —— 防止把 A 号的稿子推到 B 号。
5. **正文体检**：非 `mmbiz.qpic.cn` 的配图、站外 `<a href>`（`#锚点` 与 `weixin.qq.com` / `qq.com` / `mp.weixin.qq.com` 不算）、`javascript:` 链接，逐个点名后拒推；确认要带就 `force: true`。
6. **必须有封面**：按 `push 参数 thumbMediaId` → `渲染时定下的封面` → `账号默认 thumbMediaId` 找，一个都没有就拒推（个人订阅号在草稿箱里改封面要点好几下，漏了就是手机上那篇没有封面）。绕过同样要 `force: true` + `reason`，并且会在 `skippedChecks.cover` 里留「没有封面（force 绕过的，记得回后台补一张）」。
7. **必须真的带插图**：那次渲染台账里登记了 N 张配图、正文里却一张都没有（典型是 `upload: false` 只渲染，图没上图床），拒推；这条绕过也要 `force` + `reason`，并在 `skippedChecks.bodyImages` 留痕。
8. `账号 + 标题 + 正文` 指纹没在台账里出现过，否则要 `force: true` + `reason`。
9. **草稿箱同名预检**：拉最近 20 条草稿，标题（忽略空白差异）撞上就拒，除非 `force: true` 或显式 `checkDraftBox: false`。这一步只读，网络失败不影响推送，只在返回值 `skippedChecks.draftBox` 里说明没查成。

`force` 与 `allowRawHtml` 每次绕过都会连同 `reason` 落进台账，事后能回答「这篇是谁允许带外链推的」。

面板里 `previewFile`（带 `<!DOCTYPE html>` 外壳、用来在浏览器里看）和 `file`（真正推的裸 `<section>`）是两个东西，别混。

### 封面与插图：渲染时就把位置定好

排版阶段插件会先「排图」再排版（`src/images.js`，纯函数，不碰文件系统），规则全部可解释——每张图的为什么都写进返回值 `placement` 与 `cover.reason`：

- **封面**：`gzh_render` 传 `cover`（工作台封面或本地图片路径）最优先；没传就用这条在工作台里登记的 `production.cover`；再没有就从这条登记的配图里挑——先看文件名带「封面 / 主图 / 首图 / banner / cover」的，否则取**字节最大**的那张（大图当封面不糊），并在 `cover.reason` 里写清为什么是它、以及「要换一张：`gzh_render` 传 `cover`，或 `gzh_account_set` 配个默认封面」。挑中的封面会传成永久素材（`add_material`），素材 id 进渲染台账、进 `draft/add` 的 `thumb_media_id`，`show_cover_pic` 跟着置 1。可用图少于 3 张时封面**不独占**，正文里照常出现，免得为了封面牺牲一张插图。
- **插图**：按三级落点——① 稿子里写了 `## 第N张图：小标题` 这类占位标题（工作台的惯例），直接把标题换成那张图，标题文字变成图注；② 图台账里带了 `anchor`（对应某一节的关键词），插进那一节；③ 都没有就均匀分配到各节。位置不满意就在稿子里对应位置自己写一行 `![](...)`：**你写的位置我们从来不动**，自动安排只补你没写的。
- **末尾甩图会挪开**：稿子末尾连续堆了两张以上没图注的图（生产线的常见形态：正文五个 `##` 小节，图全甩在最后），会自动按节重新分配；开头就写好的顺序不变。
- **同一张图只插一次**：登记表里两条指向同一内容（大小 + SHA-256 相同）只插第一次，第二张的 `skipped[].reason` 写「和前面那张是同一张图（内容一样），只插一次」。
- **图注真的会排出来**：`![图注](配图1.png)` 的 alt 文字会排成图下面居中的小字；不写 alt 就和以前一模一样。
- **想完全自己控位置**：面板上点「封面与插图交给插件排：开」切成关（工具参数 `autoPlace: false`），插件就不挑封面、不插图、不挪末尾的图，照稿子原样排。
- **本地文件不在的图会点名**，不会静默少图：警告里写「另外 N 张图没能进正文：`xxx.png`（文件不在）」，`placement.skipped[]` 里也有。

## 配图压缩（超过 1MB 也能上）

微信 `uploadimg` 的硬限制是 1MB，而导出的 PNG 常在 1.1–2.4MB。插件在传图前自己压：用 DSH 自带的 Python + Pillow 起一个子进程，按「缩放阶梯 × 质量阶梯」试到预算内（长边默认压到 1440，透明铺白底，输出 progressive JPEG），结果按 `源路径 + mtime + 预算` 缓存，同一张图重复渲染不再重压。

实测（本机 DSH 自带 Python 3.12.14 + Pillow 12.3.0）：`1.36MB → 118KB`、`1.14MB → 95KB`，质量 86、尺寸 1248×832。

- 压不动（比如预算给得离谱小）不会静默丢图：`images[].error` 写明原因，顶层 `warnings` 再提醒一次。
- 压缩器不可用（没有 Python / 没有 Pillow）时同样只报警告，图按原样尝试上传。
- 非 `http(s)` 的图地址无法上传，会被丢弃并计入 `stats.droppedImages`——公众号正文里的图必须是图床地址。
- 沙箱里不能用管道抓子进程输出，所以子进程把结果写进一个 `--meta` JSON 文件由宿主读，`stdio: 'ignore'`；这条已经在自检里锁住。

### 中间显示「配图 0 张」时，只有四种原因

1. **点的是「只渲染（不传图）」**。正文里的图必须是 `mmbiz.qpic.cn` 的图床地址，没上传就没有地址，所以只能算 `stats.droppedImages`。要图进来就点 **渲染并传图**（agent 侧 `upload: true`），`images[].url` 有值、`stats.images` 才对得上。这条最容易被误解：`upload: false` 时「配图 0 张」是**必然**的，不是坏了。
2. **正文里根本没有 `![](...)` 这一行**。工作台的图有两种存法：台账 `images[]` 里登记一份，稿子正文里引用一份。只登记不引用，以前的排版就无从下手——现在会自动插（见上一节），插完在结论里写「自动插了 N 张配图：`文件` →「哪一节」」；关掉自动插图（`autoPlace: false`）时才会退回原来的警告「工作台这条登记了 N 张配图，正文里只引用了 M 张，没引用的这 X 张这次不会出现：…」。
3. **路径解析不到**。`![](...)` 的相对路径**以稿子自己所在目录为基准**：`markdownPath` 按那个文件的目录，`itemId` + `markdownFrom: "saved"` 按导出那份 `.md` 的目录（工作台把 `配图1.png` 这类副本放在条目目录里），`itemId` 默认那份（`state.json`）按条目导出目录。找不到时报错会写「按正文所在目录找：`<绝对路径>`」；粘贴进来的正文没有目录，相对路径就只能写绝对路径。台账里的 `media-desk/files/g_xxx.png` 和稿子里的 `配图1.png` 常常是**同一张图的两个副本**，所以「没引用」的判断按文件大小 + SHA-256 认内容，不会因为换了文件名就误报。
4. **台账登记的图，本地文件已经不在了**（生产机清理过、或者条目是从别的机器拷来的）。这类图不会硬插一个打不开的地址：`placement.skipped[]` 里写明「文件不在」，顶层警告点名是哪张。这时 `stats.images` 是 0，但和原因 1 不一样——警告里有具体文件名，按它重新导出或者把图拷回去。

## 设置项（DSH 设置 → 插件 → 公众号草稿推送 → 配置）

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 关掉后所有 `gzh_*` 工具、面板按钮、面板路由都拒绝执行 |
| `defaultAccount` | 空 | 不指定 `account` 时用哪个号；留空 = 必须显式指定，防串号 |
| `defaultLayout` | `teal` | 账号没配皮肤时的兜底 |
| `mediaDeskDir` | 空 | 工作台数据目录，默认 `~/.dsh/media-desk`；没有这个目录面板自动退化成粘贴 Markdown |
| `dataDir` | 空 | 本插件数据目录（账号表 / 皮肤 / 渲染记录 / 台账 / 产物），默认 `~/.dsh/gzh-publisher` |
| `autoDigest` | `true` | 缺摘要时自动摘第一段（≤110 字） |
| `allowDirectApi` | `false` | 允许 `proxyUrl` 留空时直连 `api.weixin.qq.com` |
| `maxImageMb` | `1` | 正文配图上传预算（微信 `uploadimg` 硬限制 1MB） |
| `imageMaxEdge` | `1440` | 压缩时的长边上限（320–4096）。字太多糊了就调大 |
| `pythonPath` | 空 | 指定 Python；留空自动找（先找 DSH 自带的那份） |
| `compressTimeoutMs` | `120000` | 单张图压缩超时（10s–600s） |
| `timeoutMs` | `60000` | 单次微信请求超时 |

所有字段都是 volatile：保存即生效，不需要重启插件。代理是一个**微信 API 透传**：`proxyUrl + /cgi-bin/token`、`/cgi-bin/media/uploadimg`、`/cgi-bin/draft/add` 这些标准子路径原样转发，鉴权只用一个 `X-Proxy-Token` 头。**`proxyUrl` 请填 `https://`**：`appsecret` 和 `proxyToken` 都要经过这个地址，用 http 等于把公众号密钥明文暴露在网络上；只有你自己可控的内网代理才考虑 http。所以换成任何同协议的服务都行，只要它继续透传 `/cgi-bin/*`。

## 面板与宿主之间的 `/gzh-api`

浏览器里没有文件系统，也调不到宿主工具，所以面板靠宿主 `webServer` 的一条前缀路由读数据、发动作。这条路由自己把边界钉死：

- 除 `GET /bootstrap` 外都要 `x-gzh-token`；令牌**每次激活换发**，只发给同源请求（`Origin` 必须等于自己，`Sec-Fetch-Site: cross-site` 一律拒，`Referer` 必须是自己的前缀）。令牌只走请求头，绝不进 URL。宿主重启后旧令牌失效——面板报「缺少面板令牌」时刷新页面即可。
- `GET /bootstrap` / `GET /meta` 给同一份快照（配置、账号掩码视图、皮肤、文章、两份台账、引擎状态、文件位置），差别只有令牌；这部分不联网、不含密钥，插件停用时也读得到（面板要显示那条红横幅）。
- 会改外部世界的动作只有 `POST /call`：令牌 + 同源 + 白名单内的 `gzh_*` 工具名，三者缺一不可。
- `GET /preview` 只读插件自己 `out/` 目录里的 `.html`（≤4MB），路径穿越和别的扩展名直接拒；面板用 `iframe srcdoc` 渲染，同域但不给脚本权限。

## 排版还原了什么

对着线上 `article.html` 逐条复刻：外层 `<section>` 骨架、看点三张编号卡（`01/02/03`，多于三张截断、长标题 22 字省略号）、`## INSIGHT｜标题` 这类小标签（缺省按 `INSIGHT→WHY→HOW→ACTION→WARNING` 轮转）、`15px/1.8/text-align:justify` 正文、`==下划线强调==`、`**主色加粗**`、`` `行内代码` `` 灰片、`> 金句` 左边框卡、图片阴影卡、`E N D` 渐隐分隔、文末落款与「资料领取」尾巴。一行一句就是一个段落；行尾两个空格是段内软换行（渲染成 `<br>`）。微信编辑器要求的 `<span leaf>` 包装由微信自己补，产线 HTML 里那批 `leaf=""` 是它回吐的产物，本插件不生成。

结构化语法全部**重排**而不是照搬标签，因为微信编辑器会吃掉 `<ul>/<ol>` 的 `list-style`、把 `<table>` 的样式还原得七零八落：

| 写法 | 出来的是什么 |
| --- | --- |
| `- 项` / `* 项` / `1. 项`（行首 2 空格 = 二级，4 空格 = 三级） | flex 行 + 手写符号（`• / – / ·`，有序是 `01. 02.`，子层自己重新计数）；序号不会像原生列表那样全变成 1 |
| 列表项下的缩进续行 | 接回上一项，不会掉出来变成一个孤立段落 |
| `\| 表头 \| … \|` + `\| --- \|` | 表头带主色下边线的 flex 行表 + 偶数行斑马纹；超过 4 列会给提示「手机上会很挤」 |
| ` ```js ` 围栏 | 灰底左边框代码卡，行首空格转 `&nbsp;` 所以缩进不丢，右上角标语言；` ``` ` 没闭合时按代码渲染到文末并提示，不会把后文吞掉 |
| `#### 小标题` | 主色竖条小标题（以前 `####` 会原样推出去） |
| 独占一行的 `---` | 一条 56px 细线（文档开头的 `---` 包 front matter 会整块跳过并说明，不当成线也不当正文） |

`gzh_layout_preview`（面板上的「排版样稿」）会写出 `out/preview-<layout>.html`，面板里直接内嵌显示，也能浏览器打开就是手机上看到的宽度。

## 已知限制与未验证项

- **`media/uploadimg` 与 `material/add_material` 的请求形状未做实网验证**：代码按微信官方文档写；两处上传都按扩展名声明 `Content-Type`（`.jpg` 就是 `image/jpeg`，以前一律谎报 `image/png`）。第一次真推请先 `gzh_render`（`upload: false`）＋ 一张小图，确认图床返回 `url` 再往下走。
- **代理连通性要靠你自己的号验证**：`gzh_draft_verify` 是只读的（只列草稿），拿它先跑一次，`ok: true` 就说明这台机器能通代理、令牌有效、appid/appsecret 有效、出口 IP 在白名单内。**写路径（`uploadimg` / `draft/add`）请第一次小心验证。** 代理不通可以 `allowDirectApi: true` 直连，但那要求把本机出口 IP 加进公众号后台 IP 白名单，否则会拿到 `40164`（错误信息里会直接给出这个处置建议）。
- **推送不重试**。任何失败都进台账并带上 `errcode` 和处置建议，宁可人工确认也不盲重试。
- 密钥存在 `~/.dsh/gzh-publisher/accounts.json`（文件权限跟随用户目录）。下一步准备迁到 DSH 的凭据存储；迁移前请把这台机器当成持有明文凭据的机器对待，不要把该文件同步到网盘或提交进仓库。
- **面板第一次出现可能要重启 DSH**：`package.json` 的 `dsh.client` 声明不会被热加载（`node_modules` 下的 manifest 变化不触发事件）。装好之后改 `src/client.js` 是按 rev 换的，不需要重启（也不依赖 `pnpm run dev:web`）——但**浏览器要刷新一次**，已经加载的页面还拿着旧的 Client 半。
- **改完宿主侧 `src/*.js` 怎么生效**：把插件**关掉再打开**就够了（设置 → 插件，或让 Agent 走 `plugin_manager` 的 `set_plugin` disable → enable），不用整机重启。重新激活会重注册 12 个工具与路由、换发面板令牌，并顺带跑一次账号皮肤 key 迁移；然后再刷新页面加载新的 Client 半。只改配置（Config 页）不用重载，字段都是 volatile。
- **维护者注意**：当前 DSH 构建要求每个工具都声明 `output: { schema, render }`（少了它整个插件在激活阶段就抛 `TypeError: tool "…" must declare output`），并且会用 `output.schema` 校验返回值——工具返回值必须是**无损 JSON**（不能出现 `undefined` / `NaN` / 函数）。反复 `install_bundle` 只会重复报旧诊断，正确顺序是 `remove_bundle` 再 `install_bundle`。
- Client 半是浏览器的 lazy-CJS 模块，只能用宿主的模块加载器（`window.__ModuleLoader__.load`）注册自己，React 由页面模块表提供；不能 import 其他 Harness 客户端包，样式只写 `--dsw-alias-*` / `--dsw-specific-*` / `--dsh-*` 主题变量（所以暗色自动跟随）。这几条都被自检里的正则和假渲染盯着。
